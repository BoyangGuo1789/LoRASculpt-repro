## Method Summary

`LoRA-IGP-Ponly` keeps the target LoRA adapter active for all inputs and gates only the target-specific `mm_projector` adaptation path:

```text
projector(x) = projector_base(x) + g(input) * (projector_target(x) - projector_base(x))
```

The gate is a lightweight prompt-feature scorer trained only from allowed training prompts. IconQA prompts receive gate values near 1.0, while source/general prompts mostly receive values near 0.0. This isolates projector-path drift as the dominant recoverable failure mode in this line.

## Seal Decision

This version is strong empirically, but the next paper-facing method should not keep refining this route. In particular, do not count the following as the next main contribution:

- task-aware checkpoint routing,
- simply turning LoRA off for non-target tasks,
- more prompt-form or dataset-name gating variants,
- independent checkpoint selection by external labels.

The next phase should start from the LoRASculpt baseline training paradigm and introduce a clearly different internal improvement, such as a training-time objective, LoRA module change, mask/scoring rule, regularizer, or adaptation procedure that directly targets a baseline limitation.
